# Comcast / RDK (Firebolt)

RDK (Reference Design Kit) is the open-source platform that runs on
operator set-top boxes and operator-branded TVs — Comcast Xfinity /
Xumo, Sky, Charter, Cox, Rogers, Liberty Global, Vodafone and others,
coordinated through RDK Management. For app developers the surface that
matters is **Firebolt**: the RDK application platform. An app is
HTML5/JS (very commonly a **Lightning** app) running in the box's
**WPE WebKit** browser, talking to the platform over an RPC channel.

This is one consolidated file. The RDK/Firebolt divergences from the
consumer-TV platforms are concentrated in three places: the engine is
**WebKit, not Chromium**; the lifecycle is a **formal state machine with
hard resource-release requirements**; and distribution is **per-operator
ingestion + certification**, not a store.

## Engine: WPE WebKit, not Chromium

- Most RDK-V devices run **WPE WebKit** (WebPlatformForEmbedded). Some
  operator deployments use a Chromium-based browser instead — **confirm
  per operator**.
- Consequence: **`caniuse`-by-Chromium reasoning does not transfer.**
  WPE tracks upstream WebKit, but the version on a fielded box is
  SoC/operator-specific and often years old. Check features against the
  **Safari/WebKit** column, and feature-detect at runtime.
- This is a large part of why **Lightning** (WebGL canvas, minimal DOM/CSS
  surface) dominates on RDK — it sidesteps most engine-version variance.
  If you're writing Lightning here, the `lightningjs-v2-conventions`
  skill covers the framework; this file covers the platform under it.
- No public engine-version-per-RDK-release table. Target a conservative
  WebKit baseline, transpile down, and **test on the operator's actual
  box** (they provide dev units) — there is no universal emulator.
- 1080p logical canvas; lay out at 1920×1080 with an overscan-safe inset.
- Apply the low-RAM budget from `tv-performance-constraints`: set-top
  boxes are tightly memory-constrained and the lifecycle model (below)
  will actively reclaim your GPU memory.

## Firebolt: how the app talks to the platform

- **SDK:** `@firebolt-js/sdk` (core), plus `@firebolt-js/manage-sdk`
  (settings/management surface) and a discovery SDK. Autogenerated JS
  client over an **RPC transport** (JSON-RPC-style messages) on a
  **WebSocket** between the app and the platform.
- **Connection lifecycle:** a *connection phase* (open the socket, pass
  an auth check), an *interaction phase* (requests, responses, events),
  and a *disconnection phase* (socket cleanup on teardown).
- **Modules:** `Lifecycle`, `Device`, `Localization`, `Discovery`,
  `Content`, `Metrics`, `Advertising`, `Account`, `Authentication`,
  `Capabilities`, `Keyboard`, `Parameters`, `Profile`, `SecureStorage`,
  `SecondScreen` (DIAL), `Accessibility`.
- Every call is a promise and can be **denied by capability/permission**
  — the app's **Firebolt App Manifest** declares which capabilities it
  uses, and the operator grants them. A call for an ungranted capability
  rejects; handle it, don't assume.
- `Device.distributor()` / `Device.platform()` / `Device.model()` /
  `Device.version()` — branch behaviour on these, since "RDK" spans many
  operators and SoCs.
- **Testing:** **Mock Firebolt** ("Mock Firebolt OS") — a local mock
  transport that answers Firebolt calls and fires lifecycle events from
  JSON config, so you can develop without a box.

## Lifecycle — a formal state machine

Firebolt's `Lifecycle` module states: **`initializing`**, **`inactive`**,
**`foreground`**, **`background`**, **`suspended`**, **`unloading`**.

- `Lifecycle.ready()` — call once the app is fully loaded and
  interactive. **Do not dismiss your splash before this.**
- `Lifecycle.listen((event, value) => …)` / `Lifecycle.once(...)` —
  subscribe to transitions.
- `Lifecycle.state()` — current state.
- `Lifecycle.close(reason)` — ask the platform to move the app out of
  focus / end the session (this is your Back-at-root action).
- `Lifecycle.finished()` — call **after** you've handled the `unloading`
  event and released listeners; tells the platform it may tear the app
  down.

What the states mean for your app:

| State | App should |
|---|---|
| `initializing` | Loading; platform connection being established; nothing visible yet. |
| `foreground` | Visible and interactive; full resources. |
| `inactive` | Visible-but-not-focused / transitioning; pause non-essential work. |
| `background` | Not visible; keep only what a fast return needs; stop rendering and animations; pause/stop video. |
| `suspended` | **Release GPU resources.** Deallocate the EGL surface, GPU textures and other GPU memory, and any memory not needed for a hot launch — the platform shrinks your graphics surface (often to 1×1) and cuts your CPU. |
| `unloading` | Final teardown: remove listeners, `Lifecycle.finished()`. |

Underneath, RDK's **App Lifecycle 2.0** can go further — a `suspended`
app that has released enough is **hibernated** via **MemCR** (memory
checkpoint/restore): the process is terminated and its state snapshotted,
then restored on next launch. **If you don't release GPU/memory on
`suspended`, you block hibernation and become the first candidate for
outright termination.** On the way back, reallocate the EGL surface and
GPU textures on resume; the platform restores your graphics plane to
full screen.

Practical releasing path on `background`/`suspended`: stop the render
loop, drop WebGL/canvas textures and backdrops, `pause()` + tear down the
video pipeline and DRM session, clear timers/observers, persist resume
state (screen, playhead) — the same discipline as the other platforms,
but here it's a **specified requirement**, not just good practice.

## Remote input

- **Firebolt does not define a proprietary key API.** Remote key presses
  arrive as ordinary browser `keydown` events (or through Lightning's key
  handling on top of them).
- D-pad and Select map to the usual web values — arrows **37–40**,
  Enter **13**. **Verify Back and any other keys on the operator's
  box**; RDK covers many remotes (Comcast XR11 / XR15 voice remotes,
  plus HDMI-CEC and third-party RF4CE units) and the codes are not
  guaranteed to match webOS's `461` or Tizen's `10009`.
- Don't assume colour buttons or a full media-transport cluster —
  operator remotes vary; make D-pad + Select the primary path for every
  action.
- **Text entry goes through the `Keyboard` module** (`Keyboard.email()`,
  `Keyboard.password()`, `Keyboard.standard()`), which asks the platform
  to present its own input UI and returns the string — you generally do
  **not** render your own on-screen keyboard.
- No pointer/cursor model.
- See `tv-focus-and-navigation` for the focus model this feeds.

## Media and DRM

- Firebolt's promise is a **common interface to the platform's video
  playback, DRM, graphics, and video-security** stack; it "works with a
  wide variety of DRMs and SoC video security integrations."
- In practice a web/Lightning app plays through **HTML5 `<video>` +
  MSE/EME**, and the decode happens on a **hardware video plane behind**
  the WPE graphics surface — punch a transparent hole in your UI over the
  video rect and keep them aligned on resize, as on Tizen.
- **DRM:** PlayReady and Widevine are both common on operator boxes;
  Widevine **L1** / hardware security is the norm for premium content.
  The exact supported systems and levels are **operator/SoC-specific** —
  get them from the operator's integration docs.
- One active decode; release it on `background`/`suspended`.
- Codec/HDR support is per-box — read `Device` info and feature-detect.

## Distribution and certification

- **There is no consumer app store.** Each operator **ingests** your app:
  you provide a hosted **app URL** and a **Firebolt App Manifest**
  (identity, required capabilities/permissions, lifecycle traits,
  intents it handles). The operator hosts/points to it and grants
  capabilities.
- **Certification is two layers and per-operator:**
  1. **Firebolt Certification** — conformance to the Firebolt API
     contract and lifecycle requirements (there's an RDK certification
     test suite).
  2. **The operator's own premium-app certification** — the rigorous,
     studio-driven pass (performance, resource release, DRM robustness,
     accessibility, resume behaviour). This is the slow one.
- **One codebase, many operators — but each operator is a separate
  ingestion, capability grant, cert pass, and release.** "Ships on
  Comcast" does not mean "ships on Sky."
- Updates are re-certified. Keep the URL the operator reviewed pinned to
  the certified build.

## What to get from the operator

Because behaviour varies by operator and SoC: the WebKit (or Chromium)
engine version on the target boxes; the exact remote key map; supported
DRM systems and security levels; which Firebolt capabilities they grant;
their App Manifest schema version and lifecycle traits; and their
certification checklist and cadence.
